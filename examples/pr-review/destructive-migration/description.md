# Перенести статус выполнения заказа в отдельную таблицу

Статус выполнения хранится в `orders.status` и обновляется consumer’ом. Переносим его в таблицу `order_fulfillment`, чтобы в следующем релизе хранить историю статусов. Миграция 006 переносит данные и удаляет старый столбец.

## Критерии приёмки
- После обработки события Kafka `GET /api/orders/:id` возвращает `status=completed`
- Повторный `POST /api/orders` с тем же `Idempotency-Key` возвращает тот же заказ
- Откат приложения на предыдущую версию после применения миграции не ломает оформление и чтение заказов
