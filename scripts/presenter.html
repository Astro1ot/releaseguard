Увидеть восстановление.

Каждая кнопка запускает настоящий тест на вашем компьютере. Сначала запустите стенд, затем проходите сценарии по порядку. Во время отказа откройте статус-страницу в соседней вкладке.

Статус и тестовый заказ ↗Grafana ↗Алерты ↗
00 / ПОДГОТОВКА

Запустить стенд

Собрать приложение и запустить PostgreSQL, Redis, Kafka и мониторинг. Первый запуск скачивает образы.

01 / ЗАКАЗ

Проверить покупку

Создать заказ, дождаться обработки через Kafka. 40 одновременных повторов должны создать один заказ.

02 / КЭШ

Отключить Redis

Каталог продолжает работать через БД. Статус фиксирует сбой, затем Redis автоматически запускается снова.

03 / ОЧЕРЕДЬ

Отключить Kafka

Заказ остаётся в PostgreSQL и ждёт обработки. После запуска брокера заказ должен завершиться.

04 / НАГРУЗКА

Всплеск запросов

Nginx ограничит часть запросов кодом 429. Приложение должно остаться доступным, без ошибок 5xx.

05 / БАЗА ДАННЫХ

Миграция под записью

Проверить lock_timeout, затем добавить поле и индекс, пока создаются 150 заказов.

06 / KUBERNETES

Подготовить кластер

Создать отдельный kind-кластер и установить рабочую версию. Нужны kind, Helm 3 и kubectl. Повторный запуск сохраняет секреты.

07 / РЕЛИЗ

Неудачный релиз

В отдельном kind-кластере: сломанная версия → бизнес-тест → откат → проверка восстановления. Сначала выполните шаг 06.

Результаты этой сессии

Пока нет завершённых сценариев.

Остановка сохраняет данные PostgreSQL. Не закрывайте панель во время сценария. Панель слушает только 127.0.0.1 и не входит в публикуемый контейнер приложения.
